Date: 2026-11-18. Source `../mylonex-nextjs`; destination `adminfr` / `adminbr`. This audit was saved before new parity implementation. It extends, not replaces, the previous catalog audit and SQL review. No shared database write or migration is authorized by this work. Public schema metadata was read in a READ ONLY transaction.

This is a feature-by-feature implementation project, not a claim of existing complete parity. `docs/old-admin-source-inventory.json` records 91 source files with imports, exports, DB operations and explicit role checks. The role-check search also includes supplier creation, admin server actions, tracking services, admin layouts and catalog wrapper delegation; marketing Header role checks are navigation only, not an authorization substitute. Admin API catalog handlers delegate to role-checked services. No independent admin-only API outside these paths was found by the role/ADMIN scan.

## Planned safe implementation order

P1: shared validated paging/DTOs/auth-state guard; correct dashboard/buyer data semantics; guarded RFQ and quote operations; exact tracking read model; detail navigation. P2: retain catalog restore and isolate its heavy importer. P3: sample quote/rejection + accepted-source delivery. Backend repositories/services precede UI wiring. Tests use a disposable local schema-only clone and synthetic records. External notifications are not sent by test runs. Persist old/new source/API coverage in the final report and do not label deferred dispatch or re-match complete.

## UI reference discipline

The old authenticated catalog was inspected in Chrome in the preceding work. This expanded audit inspects route/React/domain source; it does not claim authenticated browser verification of every screen. The old Admin UI uses Platform Metrics, buyer engagement states converted/active/registered/inactive, grouped queue/detail layouts, sample quote drawer, Order Master View, plus accepted production/sample and delivery domain functions. New UI must adopt these concrete workflows rather than rebrand generic cards. Catalog typography corrections are retained.

## Explicit removal decisions

No existing old Admin feature is removed as obsolete. Unsupported buyer account moderation, persistent drafts and capacity ranges are not invented. Legacy inquiries remain included in metrics. Existing Order records remain accessible alongside accepted quote/sample sources; these represent different platform concepts and must not be conflated.
